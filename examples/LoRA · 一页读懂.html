LLMOps · 模型微调

LoRA：不重写大书，
只训两张便利贴

LoRA（Low-Rank Adaptation，低秩适配）是一种微调大模型的方法：把基座模型的权重全部冻住，一个不改；只在旁边外挂两个小矩阵来训练。训完，模型就学会了新任务。

先说清对比。全量微调像把整本教材重写一遍——模型的每个参数都要动，费显卡、费时间，还得到一整本新书。LoRA 像在教材上贴便利贴：书还是那本书，你只写那两张贴纸；要换任务，撕下来换一张就行。

02

原理：一本冻书 + 两张贴纸，怎么算

场景动画 · 机制本身在动

模型里一层权重就是一个大矩阵 W。微调想做的事，是给它加上一个变化量 ΔW。LoRA 的关键假设是：ΔW 本身是「低秩」的——真正要改的方向没几个，所以不用存一整个大矩阵，用两个瘦矩阵 A、B 相乘就能近似它。

W′ ＝ W ＋ ΔW ＝ W ＋ B·A

W 是 d×k 的大矩阵；A 是 r×k（瘦高），B 是 d×r（扁宽），r 远小于 d 和 k。训练时 W 冻住、只更新 A 和 B；推理时既可以现算 B·A，也可以先合并成 W′ 再用。

切到「合并后推理」：便利贴誊进书里，下路关闭，输入只走 W′ 一条路，推理不增加任何延迟。页面内动画为本地模拟，不连接真实训练环境。

为什么敢用小矩阵近似？

论文的实证发现：微调时权重的变化量虽然住在很大的矩阵里，但「内在维度」很低——真正起作用的改动方向就那么几个。r 就是你愿意给的方向数：给少了学不像，给多了浪费，8 和 16 是最常用的起点。

为什么这件事划算？

可训参数降到不到 1%，显存和训练时间跟着降；训完只存几 MB 的适配器，一个基座可以配很多个适配器轮流上岗——给财务、客服、代码各训一张贴纸，推理时按需换。

真刀真枪：同一套 LoRA，换基座，结果天壤之别

教训：LoRA 放大的是基座已有的底子，不会无中生有。tiny-gpt2 本身几乎不会答题，贴多少便利贴都教不会；换一个像样的基座，同一套贴纸立刻见效。选基座，先于调 r。

流程讲解 · 全 6 步（打印版；屏幕上点上面的按钮逐步看）

1. 备数据

准备「指令—回答」样本：给模型看问题长什么样、答案该长什么样。LoRA 学的是你这批样本的规矩，所以格式要统一、答案要靠谱。
myth：以为数据越多越好；其实格式一致、答案靠谱的几百条，胜过几万条噪声——脏数据训出糊贴纸。

2. 冻基座

加载基座模型，把它全部权重冻结（不再更新）。从这一步起，基座在整场训练里只负责「被参考」，一个参数都不改。
myth：以为冻住就学不了了；其实要学的是外挂的 A、B，基座冻住正是 LoRA 省钱的根源。
base：已冻结
train：0（基座侧）
adapt：未挂载
prod：—

3. 挂适配器

给选定的层挂上 A、B 两个小矩阵：先定 r（8 或 16 起步），再定贴哪几层（target_modules，常用注意力的 q / v 投影），alpha 常取 r 的 2 倍。
myth：以为 r 越大越好；其实 r 大了账单线性涨、还更容易过拟合，先小后加。
base：已冻结
train：65,536（r=8 示例层）
adapt：已挂载

4. 训练

正常跑反向传播，但梯度只更新 A 和 B——回看 ② 屏的账本：轮次往前走，基座被改动的参数恒为 0。可训参数不到 1%，普通显卡也跑得动。
myth：以为 LoRA 只是省显存、速度一般；其实可训参数少，训练通常比全量微调快得多。

5. 评估

用没参与训练的留出题验收，并和基座原样答题对比。本页作者的实跑：Qwen2.5-0.5B 从 0% 到 100%；而 tiny-gpt2 换什么贴纸都是 0%。
myth：以为训练 loss 降了就是学会了；其实只认留出集——没见过的题答对，才算真学会。

6. 合并 / 部署

两条路：把 ΔW 加回 W 合并成 W′ 单独部署；或不合并，留着适配器文件，推理时按任务热插拔——一个基座配多张贴纸轮流上岗。
myth：以为合并会掉精度；其实合并就是精确相加 W＋B·A，不掉精度，还省掉推理时的额外计算。

秩 r控制适配器的容量（可训参数量）贴纸的厚度，先从 8 或 16 起步

自测三题（带解析）

1. LoRA 训练时，真正被更新的参数是？

解析：选 B。基座全程冻结（② 屏账本里「基座被改动的参数」恒为 0），梯度只流进 A 和 B。

2. 把 r 从 8 调到 64，会发生什么？

解析：选 A。可训参数 = r×(d＋k)，与 r 成正比（③ 屏拉一遍就看见）；但容量变大不等于效果变好，还更容易过拟合。

3. 实测里 v1 用 tiny-gpt2 训完还是 0%，最对的解释是？

解析：选 C。同样的流程换 Qwen2.5-0.5B 立刻 0% → 100%（③ 屏）。LoRA 是放大器，不是无中生有的老师。

必踩的坑（集中清单）

  • 基座太弱还硬训：先换基座，再谈调参——顺序反了全是白干。
  • r 不是越大越好：账单随 r 线性涨，效果不跟着线性涨，还更容易过拟合。
  • 数据脏：格式不一、答案没谱的样本，训出来的贴纸也是糊的；质量先于数量。
  • 重复合并：同一张适配器 merge 两次，等于 ΔW 加了两遍；部署前核对合并状态。
  • 库版本打架：peft 与 torchao 等依赖版本冲突会直接报错——本页作者实测，先卸载 torchao 0.10.0 再装 peft 才跑通。
一句话带走

LoRA ＝ 冻住大书、只训两张便利贴：用不到 1% 的参数把大模型调到你的任务上；但贴纸救不了弱基座。
