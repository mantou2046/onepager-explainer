BM25：给关键词打分的
那套老规矩

接你这两天看的检索线：余弦相似度管「意思像不像」，BM25 管「字面对没对上」。你刚剪藏的 RRF，要合并的两路里就有一路是它。这页讲它怎么给每篇文档打分、排名。

01 · 是什么

先打个比方：它是个按线索打分的侦探

你报上几个关键词，BM25 挨篇文档核对：这个词出现没有、出现几次、这个词稀不稀罕、这篇文档长不长。核对完给每篇打个分，从高到低排队。它不读意思，只对字面——词对上了才算，对不上，写得再相关也是零分。

最笨的打分法是直接数词：出现几次得几分。毛病马上就来——长文档词天然多、把关键词重复一百遍就能刷到第一、满篇都是的口水词和一锤定音的稀有词一个价。BM25 就是给「数词」立了三条规矩，把这三个毛病一个一个堵上（第二屏细讲）：

一篇文档的得分 = 每个问题词的（稀有度 × 打折后的出现次数）全部加起来，再按篇幅拉平

名字的来历不用当回事：BM 是 Best Matching（最佳匹配）的缩写，25 是这套打分法在实验室里迭代到的版本序号。它还有个老家名字叫 Okapi BM25，见到别以为是另一个东西。

顺带认识几个词，只认这几个就够往下读

词它管什么白话解释
语料库被检索的全部文档的集合侦探要翻的整个档案室；「稀有」是相对它而言的
词频一个词在一篇文档里出现几次线索在这篇里露面的次数
稀有度（IDF）一个词在整个库里有多罕见，越罕见权重越高满档案室都有的特征不值钱，只在几篇里出现的才是强线索

02 · 三条规矩

规矩一：出现算分，但越堆越不值钱

下面这段动画演的就是「饱和」：一篇文档里「苹果」一个一个往里加，看每个新加的词还涨多少分。第一个 +0.29，第二个只剩 +0.11，到第十个只剩 +0.007——不是不给分，是越给越小气。想靠重复关键词刷到第一，在这条规矩面前没戏。

「苹果」已出现 1 次 · 这个词得分 0.29 · 刚这一次只涨了 +0.29

右边曲线就是左边的账：涨幅一路变平，最后贴着天花板走。k1 决定的就是这条曲线弯得多快。

规矩二：稀有词更值钱

问题里每个词先称一称稀有度：在全库越多文档里出现的词，越不值钱；只在少数文档里露面的词，一出现就是强信号。第三屏的小库里，「苹果」在 5 篇里占了 4 篇，稀有度只值 0.29；「手机」只占 3 篇，值 0.54。所以评测篇靠「手机 ×4」拿了大头分，果园篇把「苹果」写了 3 次也只得 0.49——押错词，堆多少次都白搭。

规矩三：长文档要拉平

长稿篇和短帖篇命中的词一模一样（苹果 ×1、手机 ×1），得分却差了近一倍（0.60 对 1.11）。原因：长稿有 60 个词，命中被篇幅稀释；短帖只有 12 个词，同样的命中密度高得多。BM25 拿每篇的长度跟全库平均长度比，长的打折、短的找补。把旋钮 b 拧到 0 关掉这条规矩，两篇立刻同分（都是 0.83）——第三屏可以亲手验证。

真公式长这样（不用背，认个脸熟）

得分 = Σ 稀有度 × [ 次数 × (k1+1) ÷ ( 次数 + k1 × (1 − b + b × 本篇长度 ÷ 平均长度) ) ]

对着三条规矩逐段看：稀有度管规矩二；中括号里分子分母同涨管规矩一（次数越大，分式越贴近 k1+1 这个天花板）；分母里带长度比的那截管规矩三。以后在文档和面试里见到它，知道每块在干嘛就够了。

04 · 流程讲解

六步：一道问题是怎么变成排名的

点着步骤往下走，每一步旁边的迷你排名都会同步变到那一步该看的样子——不用翻回第三屏。

问题：苹果 手机

流程讲解（打印版 · 全步）

  1. 先把问题拆成词（分词 · 去掉没意义的词）：用户的问题先被切开：「苹果手机壳」和「苹果 手机」在 BM25 眼里是两回事。拆错词，后面算得再准也白搭——中文检索里分词质量直接决定 BM25 的上限。
  2. 挨篇数词（每个词出现几次，先记原始账）：对每篇文档数一遍：问题词各出现几次、多长。原始账是：评测篇苹果 ×2、手机 ×4（长 40）；短帖篇各 ×1（长 12）；长稿篇各 ×1（长 60）。只看原始账，长稿和短帖打平。
  3. 次数打折（饱和 · 旋钮 k1 管）：次数先过饱和这道关：出现 1 次的含金量最高，往后每次涨分递减。评测篇的手机 ×4 不是 4 倍分，折完约当 ×1.6 用；果园篇苹果 ×3 折完约当 ×1.7 用。k1 越大，曲线弯得越晚、堆词越划算。
  4. 乘上稀有度（IDF · 稀有词身价高）：每个词的折后分再乘它在全库的稀有度：苹果占了 4/5 的文档，只值 0.29；手机占 3/5，值 0.54。评测篇的大头分来自手机这一项（0.87），不是来自堆得最多的苹果。
  5. 按长度拉平（长度规矩 · 旋钮 b 管）：最后按篇幅找补：长稿 60 个词是平均（31 个）的近两倍，分数被压到 0.60；短帖只有 12 个词，被抬到 1.11。b = 0 时这一步整步跳过，两篇同分 0.83。
  6. 排名与搭档（BM25 只是混合检索的一条腿）：最终排名出炉。但记住 BM25 的边界：它只认字面：问题写「退钱」、文档写「退款」，它一分不给——那是余弦相似度那路的活。真实系统里两路各出一份排名，再用 RRF 这类办法合成一份（就是你剪藏的那篇在讲的事）。最终排名：评测 1.24 ＞ 短帖 1.11 ＞ 长稿 0.60 ＞ 果园 0.49 ＞ 无关篇 0。

必踩的坑（集中一张卡）

  • 它只认字面，不认意思：问「退钱」、文档写「退款」，BM25 给 0 分；型号、人名、编号这类精确词它最强，同义词、换说法它是瞎子。别指望它单独撑起一个 RAG。
  • 分数不能跨库、跨次比：稀有度是拿当前库算的，换一个库，同一篇文档分数全变。拿 BM25 分数当「相关性百分比」、或拿两次检索的分数比高低，都是错的。
  • 分词切错，全盘皆输：「苹果手机」切成一个词还是两个词，命中结果完全不同。中文用 BM25 前先验分词，别默认搜索引擎都处理好了。
  • 默认旋钮不是万能药：k1 = 1.2、b = 0.75 是通用默认值；库里文档长短悬殊、或全是短文本时还照抄，长文档会被压得过头或短文档占尽便宜，要按自己的库验。
  • 标题和正文一个价：裸 BM25 里词出现在哪都一样算；真实系统通常给标题里的词单独加权。自己搭检索时漏了这层，排名会怪。

最容易混的三组

BM25 vs 向量检索（余弦）：两条腿，两种眼力

BM25 对字面：词必须出现，胜在精确——查型号、编号、人名、原文句子，它又快又准；向量检索对意思：换个说法、近义词也能捞回来，胜在不认死理。各自的瞎区正好是对方的强项，所以现在的标准做法是两路都跑、再合并排名（混合检索），而不是二选一。

BM25 vs 直接数词：差的就是三条规矩

直接数词没有饱和、没有稀有度、没有长度拉平：长文档和堆词文档永远赢。BM25 不是另一个物种，就是给数词立完规矩的样子。面试里说「BM25 是 TF 的改进版」，改进点就是这三条。

BM25 vs TF-IDF：祖孙关系

TF-IDF 是更早的打分法：词频 × 稀有度，思想和 BM25 同源。BM25 在它身上补了饱和（词频不再线性涨分）和长度拉平这两件 TF-IDF 没有或做得粗的事。见到 TF-IDF 别慌，会了 BM25，它就是少两条规矩的简化版。

自测四题（点开看答案）

1. 两篇都出现「退款」3 次，一篇 200 词、一篇 2000 词，哪篇分高？

200 词那篇。同样的命中，篇幅短十倍、密度高得多，长度拉平会把短篇抬上去、长篇压下来。

2. 问题词在库里每篇文档都出现，它对排名还有用吗？

几乎没用。哪篇都有，稀有度趋近于 0，乘完之后每篇都加差不多的一点点分，拉不开差距——真正决定排名的是那些只在少数文档里出现的词。

3. 把关键词在一篇里重复 50 次，能刷到第一吗？

不能靠这个。饱和规矩下，第 50 次涨的分约等于零，这个词的得分贴着天花板（稀有度 ×（k1+1））走。堆词最多把这一个词的分数堆满，超不过去。

4. RAG 里已经有了向量检索，为什么还留 BM25 这一路？

因为向量对精确字面不敏感：型号、编号、人名、专有名词这类「必须一字不差」的东西，向量可能捞不准，BM25 一抓一个准。两路互补，合并排名比单用任何一路都稳。

一句话带走：BM25 就是给「数词」立了三条规矩的打分法——出现算分但越堆越不值钱，稀有词更值钱，长文档要拉平；它只认字面，所以在 RAG 里和管意思的向量检索搭档干活。

来源与口径：演示小库为本页自造的五篇玩具文档（篇长 12–60 个词），分数按 Lucene / Elasticsearch 通行的 BM25 变体复算：稀有度 = ln(1 + (N − n + 0.5) ÷ (n + 0.5))，默认旋钮 k1 = 1.2、b = 0.75；全库平均篇长 31.4 个词。关键数已独立核算：评测 1.24、短帖 1.11、长稿 0.60、果园 0.49；b = 0 时长稿与短帖同为 0.83；饱和增量从 +0.29 递减到 +0.007（第 10 次）。BM25 出自 Robertson 等人在英国 Okapi 实验室的工作，1994 年前后成形，现为 Elasticsearch / Lucene 的默认打分法。
