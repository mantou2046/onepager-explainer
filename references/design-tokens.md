# design-tokens.md —— 视觉系统与讲解器契约

> 「一页读懂」HTML 的视觉语言与结构规范。源自 K8s 演示页 → Helm 学习页两次验证。
> 目标：**换主题不换脸**——内容不同，但一眼看出是同一体系的作品。
> ⚠️ 2026-10-15 晚**四方评审定版**（字阶 / 字重 / 语义色 / 打印 / 移动端）已并入 §1–§3、§4.0、§6.1、§7；验收勾选项见 `qa-gates.md` 第 2 层。

## 0. 单文件铁律

- 整个页面 = 一个 `.html` 文件，零外部依赖（无 CDN、无外链字体/图片/JS），双击即开、可邮件发送、可离线
- 所有 CSS/JS 内联；唯一允许的外部动作：语音分支生成的 base64 音频、主视觉生图的 base64 图片（内嵌后同样自包含，见 §4.3）
- 文件命名：`<主题> 学习 · 一页读懂.html` 或 `<主题> · 一页读懂.html`

## 1. 主题与色彩

- CSS 变量驱动双主题：`prefers-color-scheme` 自动 + `html[data-theme]` 手动覆盖
- 必须有 `#th` 主题按钮，处理器范式（dom_smoke 断言此行为）：
  ```js
  $('th').addEventListener('click',function(){
    var cur=root.getAttribute('data-theme');
    if(!cur){cur=matchMedia('(prefers-color-scheme: dark)').matches?'dark':'light';}
    root.setAttribute('data-theme',cur==='dark'?'light':'dark');
  });
  ```
- 至少定义：`--bg --ink --muted --line --card`（+ 各色条用的 accent 变量）；明暗两套取值
- 浅色底深色字、深色底浅色字；不用纯黑纯白

### 1.1 语义色贯穿（一概念一色，2026-10-15 定）

- 主题里的「概念」用属性挂色，**一处定义、全页复用**：`[data-k=pdb]{--k:var(--warn)}`，再让卡片上边框、标题、节点选中态、统计圆点、浅底都吃 `--k`
- 浅底用 `color-mix(in srgb, var(--k) 7%, transparent)` 染，别手写第二套色值
- **禁止按奇偶交替上色**——底色与概念语义打架，比不上色更糟

### 1.2 深色模式纪律

- 全页**禁硬编码色**：SVG 文字 / 图形走 CSS 类 + 变量上色（SVG presentation attribute **不能**写 `var()`，必须用 class）
- 语义底色抽成变量（如 `--warnbg` / `--badbg`）并在深色主题里**重定义**
- 深色主题下 `--line` 提亮一档；位图主视觉加 `filter:brightness(.88)` 压暗；代码块加 1px 描边与页面底色分开

### 1.3 主题持久化

- 主题选择写 `localStorage`，首访跟随 `prefers-color-scheme`
- `head` 加 `<meta name="color-scheme" content="light dark">`，让滚动条 / 表单控件等原生部件跟随主题
- **主题按钮位置（2026-10-15 补）**：`#th` 必须放进**吸顶导航**、**钉在右端**，按钮 `flex:none` **不参与横滚**（链接区独立 `overflow-x:auto`）；**不许放在页首内容区**——滚下去就找不着（四件套页被实测指出）。细节见 §6.1

## 2. 字体、字阶与排版

- 中文标题默认衬线、正文无衬线，标识符 / 命令用等宽（标题字体可按下方「字体护栏」采纳，正文长文不许换成等宽 / 展示字体）
- **衬线字体栈必须同时写 `Noto Serif SC` 与 `Noto Serif CJK SC`**（再加 `Source Han Serif SC` / `Songti SC` / `STSong` / `SimSun` / `Georgia`）：只写 `CJK SC` 时，装了「Noto Serif SC」的机器族名对不上，会落到 SimSun 用**合成假粗体**，标题发虚
- 标题层级清晰；**桌面正文行长按汉字计 40 字上限**（2026-10-30 定版）。分两档判定，别混为一谈：
  | 段落形态 | 上限 | 换算（16px 字号） | 说明 |
  |---|---|---|---|
  | **多行正文段落**（≥2 行） | **40 汉字** | 640px | 长文阅读的真正行长，眼睛扫完一行要能快速找到下一行起点 |
  | **单行短句**（提示、quiz 题、kv 项、callout） | **60 汉字** | 960px | 一行超长是「一行太长」，不是行长问题；超了让它折成 2 行 |
  - **窄屏按屏宽自然折算、不设下限**——390px 减内边距只剩约 350px，16px 字号就是 22 字，属正常；**但不许为凑 40 字把字号缩到 14px 以下**
  - 拉丁混排按等效宽度折算；`ch` 单位不等于汉字实宽，英文词数测不出中文行长
- **行长 ≠ 容器宽度，收窄要收在容器上，不要收在段落上**（2026-10-30 实拍实证）：给段落加 `max-width:40em` 会在宽卡片里留出 260–460px 的空右边，文字悬在左边、卡片显得空。正确做法是**正文所在的容器收窄**——正文该待在 `.narrow` 里（`.narrow` 本身收 640px），表格/演示型卡片才用宽容器
- **混排里数字与单位是一个整体，不许拆行**（2026-10-30 加）：`¥1,280`、`3.5mm`、`≤50KB`、`q78`、`−5%`、`320×1.3`、`2026-10-30`、`v1.0.0` 这类片段用 `white-space:nowrap` 或 `&nbsp;` 局部锁住；断行只许断在片段之间，不许断在数字与单位、数值与符号、版本号与小数点之间。窄屏放不下时**先改容器内边距或排列，不许靠缩小字号硬塞**
- **需要纵向比较的数字用 `font-variant-numeric: tabular-nums`**（统计数字、参数表、对照表的体积 / 价格列），并实测该字体是否真支持等宽数字——不支持时退回显式列宽对齐，不许假设生效
- **字体护栏（2026-10-25 定，量子页评审实证）**：正文长文一律**系统无衬线栈**——不许拿等宽 / 展示字体排长段阅读；ui-ux typography 域采纳的字体若为等宽（如 Roboto Mono）或无中文字形，**只许**用在公式、眉题 / 标签、统计数字、短代码处；标题可采其标题字体（如 Exo），无中文字形时中文回退本地无衬线、拉丁 / 数字 / 公式由采纳字体呈现。采纳字体本地没有时自行下载 woff2（优先可变字体单文件、仅 latin 子集）base64 内嵌 `@font-face`，**禁止外链**；页脚注明这一边界与内嵌体积
- **禁止**：居中大 Hero + 渐变、单行标题里给一个词换色/斜体、无信息量的编号装饰（01/02/03 只在内容真是序列时用）

### 2.1 字阶定版 6 档（2026-10-15 晚四方评审 + A/B 对照后定稿）

全页**只许这 6 档**——不再有 13 / 13.5 / 14.5 这类感知不出差别的半档，也不再有 17 / 21 / 30 旧档：

| 档 | 用途 |
| --- | --- |
| 32 | 主标题 h1（用 `clamp(26px,5vw,32px)`，全页唯一） |
| 24 | 二级标题 h2、数据大字 |
| 19 | 强调段 `.big`、三级标题 |
| 16 | 正文 |
| 14 | 副标、表格、按钮、说明、代码、公式、步骤钮、导航链接、章节眉题 |
| 12.5 | 标签、表头、脚注、图注 |

相邻档比值 ≥1.125；小于此值的档一律合并或淘汰。

### 2.2 字重收敛

- 字重只用 **400 / 600 / 700**；`800` 只留给统计数字等个别处
- 强调段 `.big` 用 19 / 700，**不许整段 800 压人**（全是重点 = 没有重点）

### 2.3 版心分层与眉题

- 版心分两层：正文段落收窄到 **640px（≈40 汉字，§2 定版）**，演示与表格可用全宽（**约 1000px**）。**正文与宽容器分离是硬要求**——正文待在 `.narrow`（640px）里，表格/演示型卡片才占宽容器；反过来把正文塞进 1000px 容器（实测最长 72 汉字）就是版心规则没被执行（2026-10-30 修）
  **落地配方（2026-10-30 抑郁症页样板验证过）**：
  ```css
  /* 正文容器统一 640px —— 表格/演示型容器不要加进来 */
  .prose,.narrow,.hero-txt,.help,.narrow-card{max-width:640px}
  ```
  - `.prose` / `.narrow` / `.src`：改版心变量或类即可（`--maxw:640px`）
  - **纯文字卡片**加类 `.narrow-card`（卡片整体收窄，不在段落上加 `max-width`——那会留空右边）
  - **讲解器步骤正文**（`#q-say` / `.stepbody`）所在的纯文字卡同样加 `.narrow-card`；实测胶囊行在 590px 内容宽仍一行放下
  - **hero 单列时**（≤900px）左栏也要限宽，否则 768px 下会跑到 46 字
  - **窄块与宽块并存在同一 section 是正常版式**，但窄块的右缘要彼此对齐（读起来才像「正文列 + 数据卡」而不是「尺寸没统一」）
  - **29 页全量落地后的最终配方（2026-10-30）**：多数页的正文**不在** `.narrow` 里（实测 Prompt 版本化超标段祖先链是 `div.tree#960 > section#960 > div.wrap#1000`），收 `.narrow` 对正文无效——**改用段落级限宽**：
    ```css
    p,li,.lead,dd,blockquote{max-width:40em} /* 640px */
    table{table-layout:fixed;width:100%} /* 收窄后表格按比例分配列宽、文字自动换行，不裁切 */
    ```
    - 段落级 `max-width:40em` 在正文卡片本身较窄（724px）时几乎无副作用；**只在宽卡片（抑郁症页）用容器级方案**，避免留 260–460px 空右边
    - `table-layout:fixed;width:100%` 是收窄后表格的**必配**：实测 5 列 984px 表收到 640px 后完整显示、无滚动条；不加会裁切
    - **不动骨架**（`.wrap`/`.main` 保持 1000px）——实测 28/29 页表格宽度 >760px，收骨架会压扁所有表格
    - **不动 DOM**：纯 CSS 追加到 `</head>` 前（`</head>` 全 29 页唯一，是安全锚点）
    - 落地后 29 页 0 溢出、0 间距覆盖失败，正文段落全部 ≤40 字（原 126 段超标、最长 72 字）
- **眉题（`.tag`，如「01 · 是什么」）不是标题**：只负责报幕，定版 14px、主色 + 短标线；全页 h1 唯一，眉题再放大也只许到 14，**不许与 h2 抢层级**

### 2.4 中文断行修复顺序（2026-10-30 加，借章法四级取舍）

标题或正文在窄屏被拆得难看时——孤字独占一行、「为什么」被拆成「为什／么」、专名或量值被切断——**按这个顺序修，不许跳级**：

1. **先查容器**：标题是不是被旁栏、固定宽度、过大内边距或 `max-width` 挤窄了？能改排列就不改字。**这一步最常见，也最常被跳过。**
2. **少量稳定短语局部不换行**：`<span class="nw">`（`white-space:nowrap`）或 `&nbsp;` 锁住专名、型号、量值。**长机构名、整句、长标识符不许整块锁死**——锁死了窄屏直接溢出，比拆开更糟。
3. **再调字号**：**只许在 6 档内用 `clamp()` 或降一档，不许为凑一行新增档位、不许跳出 §2.1**。（本技能与章法的分歧点：它允许「微调字号阶梯」，我们的 6 档是硬约束，这条不照抄。）
4. **最后才用 `text-wrap:balance`**：它只改断点选择，**不保证中文语义正确**；`balance` 生效 ≠ 断行对了，必须回头看真实行片段。

**修完必须逐行读一遍**：把该元素的实际行文本读出来（DevTools 或截图），确认无孤字、无动词 / 助词被拆散、无专名或量值被切断。**几何上不溢出 ≠ 断行自然**——机器测得出溢出，测不出「读着别扭」。

**禁止的假修法**：插普通空格、插零宽字符、删字、替换标点来「凑整齐」。用户锁定文案时只许排版解决。

**先跑脚本再人读**：`node scripts/text_check.mjs 页面.html` 会把每个 h1/h2 的实际行片段、末行字数、跨行的数字串逐条列出来（末行 1 字判失败、2 字判待人工）。但**脚本只给几何**——「抑郁／发作」被拆开它只能报「末行 2 字」，读不读得懂仍要人看行片段判断。

## 3. 卡片语言

- 卡片用**上边框色条**区分层次（3–5 px 实色），不做统一的 12px 圆角 + 投影
- 类比/提示/注意用 `<blockquote>`、`.hint`、callout 区分，不靠 emoji 堆砌

### 3.1 纵向节奏三档（2026-10-15 定）

区块之间（卡片 `margin` **36**）> 卡内（`padding` **24**）> 组内（`gap` **16**），**三者不许同值**——同值 = 一摞等距的砖，章节感消失。

## 4. 五屏结构（推荐默认）

| 屏 | 职能 | 必备交互 |
| --- | --- | --- |
| ① 是什么 | 问题引入（不用它会怎样）+ 核心名词表 + 一个核心公式卡 + **中英术语对照表** | 名词表 + 术语对照表 |
| ② 结构/原理 | 主题的核心组成 | **可点击文件树/结构图**（点哪看哪） |
| ③ 动手 | 参数 → 结果 的因果关系 | **实时渲染演示**（滑杆/输入 → 输出高亮替换） |
| ④ 流程 | 完整上手流程 | **分步讲解器**（见 §5，语音可选） |
| ⑤ 速查与带走 | **三列速查表**（术语｜作用｜白话备注，见 §4.2）+ 易混淆对比 + **评分测验** | 折叠答案或评分测验 |

内容少的主题可合并屏，但 ②③④ 的「结构-动手-流程」骨架不建议省。

### 4.0 教学法与首屏纪律（2026-10-14 / 10-15 补）

- **学习路线置顶**：页面若对应定时学习任务（如「看 40 分钟」），时间分配放**页首第一张卡**，每段标清「看哪儿 / 看到什么程度算够」，不埋在最后一屏
- **演示要对比**：关键概念优先 A/B 对比演示（普通 vs 流式）；参数演示给全关键参数滑杆，不做单变量孤立展示
- **至少一处定制可视化**：每页至少一处为内容定做的图形化演示（时间轴 / 仪表盘计数 / 节点图 / 流程带），不能全是滑杆 + 文本输出；演示结果尽量仪表化（状态灯、计数格、进度条）
- **自测带解析 + 四处口径一致**：每题作答后给解析（为什么对 / 错），只判分不合格；**题干、选项、解析、速查表四处口径必须一致**（反例：题干「共 6 次」vs 解析「共 5 次」→ 判废）
- **首屏纪律**：hero **不许占满首屏**——桌面默认两栏（文案 : 图 ≈ **5:7**），插画不许按自然比例撑高；按变体层选「居中宣言」时改为母题下置成横幅（仍不许占满首屏，移动端母题限高或回两栏堆叠）；定时任务页的时间分配卡必须在 **900px 高视口**的首屏内露出第一行（验收线）
- **首屏关键数据卡（2026-10-25 实证新增）**：数据型/事实密集型主题，首屏默认放 1 张「本页最关键的 3 个数字/结论」卡（数字必须来自本页内容本身，如候选池→入选数、关键参数典型值、核心结论计数，不许编装饰数字）；纯叙事/故事型主题不强求。位置在 hero 区内、定义之后，不顶替定义与母题。
- **主题视觉母题**：hero 区要有一个与主题呼应的图形母题（如心跳页的 ECG 脉冲线 + 监测插图），用**内联 SVG** 实现，全页色彩围绕母题展开；**不许只有文字和表格开场**
- **图标节点图可用但要成体系**：emoji / 图标节点图亲和力强、可以借，但圆角、间距、字号必须服从全页同一套设计变量，不许东拼西凑
- **易混淆对比区**：⑤ 屏加折叠区，列本主题最易混淆的 2–4 组概念成对对比

### 4.1 中英术语对照表（① 屏，按场景分流）

> 硬规则 6 的落地件。**分组比堆成一张大表好用**；缩写行必须给「英文全称」列。
> ⚠️ 2026-10-21 用户两次纠正后定版：**术语表列结构按「页面主题场景」分流**，不是所有页面都套同一个模板。

**场景 A · 技术类页面**（K8s / Helm / 工具流程……第一列本就是英文标识符）：

| 组 | 列 | 内容要点 |
| --- | --- | --- |
| 一 · 缩写与系统名 | 缩写 / 英文全称 / 中文 / 说明 | 只放真缩写（RBAC、HPA、CNI、CIDR…）；全称列是硬要求，不能只给中文 |
| 二 · 对象名 | 英文 / 中文 / 说明 | 官方中文文档保留不译的（Pod、Secret、ConfigMap）写成「Secret（机密）」形式 |
| 三 · 字段·选择符·动词 | 英文 / 中文 / 说明 | `podSelector`、`scaleTargetRef`、`get/list/watch` 这类；代码块里照旧写英文 |

**场景 B · 中文原生领域页面**（诗词歌赋 / 古文 / 中医 / 法律……术语主词是中文）：

| 列 | 内容 |
| --- | --- |
| 第一列 · 中文术语 | **主词，衬线加粗**（`.t{font-weight:700;font-family:var(--serif)}`）；**不许把中文术语倒成拼音当主词**（`词牌` ≠ `cipai`），也不要用 `<code>` 等宽渲染中文 |
| 第二列 · 英文译名 | `<code>` 等宽，供读英译本的人对照；经典书名可保留转写（如 `Huajian Collection`），但只出现在括注里 |
| 第三列 · 说明 | 白话解释；与⑤屏「白话备注」列同样要求给画面/场景，别写同义反复 |

**场景 B-1 · 诗词歌赋 / 古文类**：在场景 B 的「中文术语｜英文译名｜说明」中间**插入拼音列**，列序为「中文术语｜**拼音**｜英文译名｜说明」：

- 拼音**必须带声调符号**（词牌 = `cí pái`，不是 `cipái`）；交付前逐条核实读音（WebSearch 注音版），句中多音字按文意取（「多少」古义读 `duō shǎo` 全调，非口语轻声）
- 拼音列样式与英文列区分：无衬线、小一号、弱化色—— `.py{font-family:var(--sans);font-size:14px;color:var(--mut);white-space:nowrap}`
- **判定维度是页面主题场景，不是逐个术语**：只要页面主题是诗词歌赋 / 古文，表内**所有**术语都注音（含意象、一语双关这类通用修辞词——在本页语境里它们就是词学词汇）；**其他场景一律不设拼音列**，维持原逻辑
- 移动端 `cardify()` 用 `thead th` 文本自动回填 `data-th`，加列零成本；冒烟要断言「每行格数 = 表头列数」且拼音列非空

**迁移教训（2026-10-21 踩坑）**：模板是从 K8s 页长出来的，迁到中文原生领域时**先问一句「这个领域的术语主词是什么语言」**——别让模板结构倒逼内容变形。第一列填不上英文标识符就填拼音，那是变形；填回中文才是正解。

**边界（别做过）**：`<pre>` 里的命令与 YAML、集群名 / 资源名（dev、prod、pod-reader）保留原文——译了反而难读，与「反 AI 味」一致。正文只对**叙述中首次出现**的术语内联补中文。

**收尾核对法**：去掉 CSS / JS / `<pre>` / URL 后统计正文英文词，逐一归入「已内联标注 / 已进对照表 / 属命令或标识符不需译」三类，无遗漏才算过（见 qa-gates.md 第 2 层）。

### 4.3 主视觉生成（生图优先，SVG 保底；2026-10-15 定版，2026-10-21 再定版）

**优先级（2026-10-21 用户拍板）**：**环境支持生图时就先生图**——优先用环境自带的生图工具（如 `ImageGen`，文生图 / 图生图），其次调用可轮询取图的生图模型（Canva `generate-image`）。**有具体场景的主视觉，不要默认退回 SVG**。**SVG 是保底**：生图全路不通（协议层坏 / 配额超限 / 凭证未签发 / 生图反复失败）才走 SVG 分层场景插画（配方见本节末），并页尾诚实声明。**生图不得阻塞交付**：生图流程卡住先交 SVG 版，图好了再补图版。

**图不图、从哪来（判定顺序）**

1. hero 需要**具象场景隐喻**——核心概念能逐个映射成画面元素、元素之间有空间关系（港湾 / 工坊 / 哨所 / 雷达站 / 秋夜闺房这类）→ **要图** → 按上面的优先生成
2. **纯抽象概念**（哈希 / 退避 / 队列 / 幂等）；以图表 / 流程 / 表格为主的页面；需要随主题换色或随数据变化的图；页面还会频繁改；小页面不值得多背 50KB → **不背图，用 SVG 母题**（更快、更轻、零依赖，天然吃 CSS 变量）
3. 无论走哪条路，**一页最多一张**生图（hero 主视觉），不做插图集

**生图输出约束（哪条路都要守）**：提示词里的每个核心概念必须映射成一个画面元素并逐项写明；色板点名与全页设计令牌一致；画面**禁文字 / 禁数字 / 禁水印**（AI 生字必错，文字一律由 HTML 承担）；构图主体居中、留白均匀，按 hero 两栏先想裁切，画幅约 **2:1**。

**生图工具与提示词**

- 工具**按当前环境可用的来，优先级**：环境自带生图工具（如 `ImageGen`，文生图 / 图生图）→ 可调用的生图模型（Canva `generate-image`，异步任务、轮询取图）
- **遇到同类报错别反复重试，直接降级**（2026-10-21 实证）：Canva `generate-image` 返回 `MCP error -32602 … jobId`（协议层坏，换 prompt / 比例也复现）、`create-design` 报 `quota_exceeded`（配额尽）、云端多模态 `connect_cloud_service` 返回 `{"authenticated":false}`（凭证未签发）——三条全堵即按本节末保底 SVG，同一报错重试第二次就是浪费
- **概念映射**：每个核心概念必须映射成一个画面元素，提示词逐项写明（四件套实证：雷达心电波 = 探针、带仪表围栏 = 配额、安全网 = PDB、散开定位针 = 亲和）
- **色板跟令牌**：提示词点名与全页设计令牌一致的配色，画面不许自成一派
- **画面禁文字 / 禁数字 / 禁水印**：AI 生字必错，所有文字一律由 HTML 承担
- **构图与画幅**：主体居中、留白均匀，按 hero 两栏与图版的裁切先想构图；画幅约 **2:1**

**插入 HTML：处理 → 内嵌（可执行配方）**

```bash
# 缩到「显示宽 ×1.3」+ 压 WebP q78，并直接产出可粘贴的 figure 片段
python scripts/prep_image.py raw.png --width 1280 --snippet \
  --alt "深色场景插画：雷达波与围栏节点" --caption "图注：雷达波=探针，围栏=配额"
# 实测：原图 1776×896 75KB → 成品 1280×646 25KB → 内嵌 base64 34KB（≤50KB 目标）
# 退出码 2 = 内嵌后超 50KB → 先降宽（−20%）或降质量（−8）再试
```

- 产物三件：`<name>.webp`（成品）、`<name>.figure.html`（**可直接粘进页面的 `<figure>` 片段**）、`<name>.b64.txt`（纯 base64 备用）
- 片段结构：`<figure class="hero-fig"><img src="data:image/webp;base64,…" alt="…" loading="lazy" decoding="async"><figcaption>…</figcaption></figure>` —— **`alt` 写画面内容摘要、`figcaption` 写元素 ↔ 概念的映射**，两者都必填
- 配套 CSS（缺一不可）：hero 两栏「文案 : 图 ≈ 5:7」、`img{width:100%;height:auto}`、深色 `filter:brightness(.88)`、`@media print` 里 `filter:none`
- **生成的原图留 staging 备份、不进页面**；页面里只放压好的 base64

**图片格式与体积（硬指标）**

- 格式优先 **WebP（质量约 78）**：同画质比 JPG 小 30–45%；仅当目标环境兼容存疑才用 JPG（质量 72–80、渐进式、4:2:0 色度抽样）
- 宽度封顶 = 页面实际显示宽 × **1.3**（hero 约 **1280px**）；生成原图再大也先缩放，**禁止原图直嵌**
- 体积目标 **≤50KB/张**（实证：JPG 213KB / 1776px → WebP 49KB / 1280px，整页 338KB → 119KB）
- **base64 内嵌**会再膨胀约 **33%**，按内嵌后的体积算账（`prep_image.py` 已计入并给退出码）

**呈现**

- `figure` 图版 + `figcaption` 写明元素 ↔ 概念的映射；`img` 的 `alt` 写画面内容摘要
- 深色模式 `filter:brightness(.88)` 压暗，不许亮图在深色页上跳眼

**保底：SVG 分层场景插画（环境里可用的生图路全不通时）**

先按优先级试完环境可用的生图路（自带生图工具 → 可轮询取图的生图模型），都拿到明确失败信号（协议层错 / 配额超限 / 凭证签不到 / 生图反复失败）再降级——**结论不是「算了」，是按下面的方案保底，并在页尾诚实声明**：

- 把内联 SVG 母题升级为**分层场景插画**：远 / 中 / 近三层纵深 + `feGaussianBlur` 做远景景深 + `radialGradient` 灯光晕 + `<pattern>` 窗棂纹理 + 渐变做被面 / 烟火材质；每个画面元素与一个词句 / 概念一一映射，写进 `figcaption`
- 页尾「来源与口径」**如实写明**：主视觉是矢量手绘不是 AI 生图、试过哪几条路分别挂在哪、以及生图可用时该怎么替换（2:1、WebP、≤50KB、图内无文字）——不默默换图装作无事发生

### 6.1 响应式与移动端（2026-10-15 定）

- **长页导航**：吸顶导航锚点跳屏；移动端**单行横滚**（`nowrap + overflow-x:auto` + 藏滚动条），不许换行吃屏
- **主题按钮钉右端**：`#th` 放在吸顶导航内、**不参与横滚**——链接区自己 `overflow-x:auto`，按钮 `flex:none` 钉在右端始终可点（详见 §1.3）

- **粗指针**（`pointer:coarse`）下可点元素 `min-height: 44px`
- **表格移动端卡片化**：`≤720px` 时 JS 给每个 `td` 补 `data-th` 字段名 + CSS 把行改块级纵排，**禁止无提示横滑藏列**
- 含双列表格的网格 `≤1100px` 就塌单列（等到 720 才塌，中段宽度两张表都在横滚）
- **宽表兜底**：宽表一律放进横滚容器；响应式至少覆盖桌面 / 移动两档，网格在窄屏单列化
- **窄屏横滚兜底标准件（2026-10-30 实测 13 页后定，每页必抄）**：放在主 `<style>` 之后，**自带 `@media print` 覆盖**——只加 `overflow-x:auto` 不补打印覆盖，会在打印时静默裁掉右半边（硬规则 10）

- **统计卡网格窄屏重排**：`repeat(N,1fr)` 的统计卡在 ≤480px 必须降列（如 `.dash` 改单列）。实测：320px 下 2 列 = 每列 117px，而卡片内容 185px，`min-width:0` 只能让盒子缩、文字照样溢出——**窄屏是重排，不是缩图**

## 7. 打印基线（2026-10-15 定 · 2026-10-30 补「打印完整性」）

打印的目标不是「能打」，是**打出来内容不丢**。缺内容的四种方式都静默：不报错、不提示，只有真打一份才看得见。

- ① **横滚截断**：`overflow-x:auto` 的容器（宽表 `.tblwrap`、代码块 `pre`）超出版心的部分，Chrome 打印时只打当前可见那一截，右侧直接消失。A4 纵向版心约 794px < 页面版心约 1000px，宽速查表首当其冲。
- ② **图形超宽**：宽 SVG / 横向流程图不设打印上限就被裁。
- ③ **只打当前状态**：讲解器未切到的步、没打开的 `<details>`、筛选签筛掉的条目。
- ④ **无 `@page`**：纸张与边距全靠浏览器默认，版心不可控。

### 7.1 标准件（每页必抄，缺一项算打印基线不过）

```css
@page{size:A4;margin:13mm}
@media print{
  /* 变量强制回浅色。⚠️ 必须带上深色选择器：深色变量挂在 html[data-theme=dark] 上，
     只写 :root 会被它压过 → 深色用户打印出「白纸 + 深色块」 */
  :root,html[data-theme=dark]{--bg:#fff;--card:#fff;--ink:#000;--mut:#333;--line:#bbb;--code:#f2f2f2;--codeink:#000}
  *{-webkit-print-color-adjust:exact;print-color-adjust:exact}
  nav.top,#th{display:none}
  .rv,.hero-el{opacity:1!important;transform:none!important;animation:none!important}
  /* 小卡片避断；装宽表 / 长清单的大容器反过来必须可断，否则挤出整页空白 */
  .card,.kcard,.demo,.stepbody,.q,.stat,.motif,figure{break-inside:avoid}
  .tblwrap,.scrollx,pre,table{break-inside:auto}
  /* 横滚解除 —— 少这一条，超出版心的列被静默裁掉 */
  .tblwrap,.scrollx,pre{overflow:visible!important;max-height:none!important;max-width:none!important}
  table{width:100%!important;min-width:0!important;max-width:100%!important}
  thead{display:table-header-group}
  th,td{white-space:normal!important;overflow-wrap:anywhere;font-size:12.5px}
  pre,code{white-space:pre-wrap!important;word-break:break-all}
  svg,img,canvas{max-width:100%!important;height:auto!important}
}
```

两条实测出来的硬约束：

1. **`min-width:0` 不能省**。页面里 `table{min-width:1400px}` 这类写法，光有 `width:100%!important` 压不住——实测宽表右列照旧被裁，加上 `min-width:0!important` 才进纸。
2. **横滚容器只许用统一类名** `.tblwrap` / `.scrollx`，不许自创。打印段是按名点掉的，名字不一样就点不到。

### 7.2 状态展开（纯 CSS 做不到，必须带 JS）

```js
(function(){
  var saved=[];
  function expand(){
    saved=[];
    document.querySelectorAll('details:not([open]):not([data-print-keep-closed])').forEach(function(d){saved.push([d,'a']);d.setAttribute('open','');});
    document.querySelectorAll('[data-print-expand]').forEach(function(c){
      c.querySelectorAll('*').forEach(function(el){
        if(getComputedStyle(el).display==='none'){saved.push([el,'d',el.style.display]);el.style.display='block';}
      });
    });
  }
  function restore(){
    saved.reverse().forEach(function(r){
      if(r[1]==='a'){r[0].removeAttribute('open');}else{r[0].style.display=r[2];}
    });
    saved=[];
  }
  addEventListener('beforeprint',expand);
  addEventListener('afterprint',restore);
})();
```

配套约定：

- 分页型容器（讲解器、标签页、筛选清单）加 `data-print-expand`，容器内被 `display:none` 藏起来的步 / 条目会在打印前临时摊开、打印后还原。
- **「点一下换一段」的切换器（流程讲解步骤、架构节点说明）光靠展开脚本救不回来**：内容根本不在 DOM 里，只在 JS 数组里。必须在**构建期**把数组解析出来、生成静态打印副本（`<div class="print-only">`），不能指望运行时读 `window.QSTEPS`——实测 `var QSTEPS` 也常写在页面自己的 IIFE 里，根本挂不到 window 上。副本要插在**步骤按钮容器之后**（找不到就插在 `#q-say`/`#stepDesc` 这类「当前步」容器之前），绝不能统一扔文末——否则正文中部的讲解会在最后一页才出现。⚠️ 副本里**不要用 `<pre>`**：门禁把「页面有 pre」当作「必须写 `white-space:pre-wrap`」的触发条件，会误伤本来没代码块的页面；用 `<div>` 配 `white-space:pre-wrap` 即可。
- **标签页面板（`role="tabpanel"`）光靠 CSS 展不开**：非当前面板带的是 `hidden` **属性**，而 `[hidden]{display:none}` 属 UA 样式，`display:block!important` 压不住它 → 只能在 `beforeprint` 里 `removeAttribute('hidden')`、`afterprint` 再还原。漏了这一步的代价是整页内容消失：实测 Helm 页 5 个面板只印出第 1 个，源文 8507 字 PDF 只抽出 1108 字（丢 87%）。展开时只挑 `section/div/article/main/aside/nav`，`button/input` 上的 `hidden` 是交互控件状态，不该被打印。
- **讲解器若只把当前步渲染进 DOM、其余步根本不在 DOM 里**，展开脚本无能为力 → 只能另备 `.print-only` 静态全量版。`.print-only` 的显隐**两向都要写**：屏幕 `display:none`、打印 `display:block`。只写打印端是回归 bug——脚本一建容器、一填内容，屏幕端就多出一整块重复副本。
- **有全量副本之后，还得把「当前那一步」的活容器藏掉**，否则同一段打印两遍。各页写内容的写法五花八门（`$('#x').innerHTML` / `sBody.querySelector('h3').textContent` …），静态认不出容器 id → 运行时按正文匹配：构建期把步骤数据写成 `<script type="application/json" id="printStepData">`，`beforeprint` 里找出「只命中某一步正文、且总长不超出它太多」的元素加 `.print-hide`。⚠️ 三个实测坑：① 匹配到内层元素时不能只藏它——**要 `closest()` 找到所属面板整体藏**，否则留下一个带边框的空框（机器学习页右边那个空白方框就是这么来的）；② 面板选择器**绝对不能写 `[role="tabpanel"]`**，Helm / K8s 进阶 的整个 `<section>` 就是 tabpanel，会连副本一起藏掉；③ 找步骤容器时**别漏 `<ol>/<ul>`**——机器学习页是 `<ol class="steps">`，只扫 `div/section/nav` 会让副本落到文末，页面中部只剩空框。
- **速查表分类筛选（`data-f` + `data-cat`）在打印时会漏行**：脚本用 `row.style.display='none'` 藏掉非当前分类，停在「数据」就只印数据那几行。补一条 `@media print{[data-cat]{display:table-row!important}}`（作者 `!important` 压得住内联样式）。
- **步骤数据里的「附加字段」必须一起渲染**：一步不止「标题 + 正文」，还常有 `demo`（此刻演示里，机器学习页）、`m`/`r`（以为/其实，K8s 六概念）、`do`/`done`/`plan`（MLflow 系列、MLOps 导论）。只取 `say`/`body` 会把它们整块丢掉——实测机器学习页 6 步的「此刻演示里」全没了。渲染时按 `附加字段 → 中文标签` 映射单独成行；正文自带「以为：」这类前缀时别把标签再叠一遍。纯坐标字段（`x/y/z/c/vis`）不是内容，跳过。
- 自测答案 / 解析等**本该藏**的内容不进 `data-print-expand`，装它的 `<details>` 加 `data-print-keep-closed`，脚本会跳过。
