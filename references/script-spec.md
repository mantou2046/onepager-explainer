# script-spec.md —— 语音讲稿写作规范

> 只用于可选的 TTS 语音分支（默认关闭）。**讲稿质量 = 语音质量的上限**：
> edge-tts 只是朗读器，念错、拗口、太长，锅都在讲稿。写完必须人审再合成。

## 1. 分段

- 一个 `.txt`，**空行分段**，一段 = 讲解器的一步（`step01`…`stepNN`）
- 每段 40–110 个中文字符（RATE -5% 下约 15–35 秒）。超 110 字必拆，短于 40 字几句并一段
- 段与段之间信息自洽：听单段也能懂，不依赖「上一段我们说到……」

## 2. 口语化

- 短句优先，一句一个意思；少用从句套从句
- 用「你/我们」，动词开头带动作感（「找 Chart」「装一个试试」）
- 书面连接词改写掉：「综上所述→所以」「需要注意的是→注意」「如下表所示→看这张表」
- 命令照念时可以念参数名，但别念一长串 flag；超过 2 个 flag 就概括

## 3. 专有名词读音表（已知坑）

| 写法 | 处理 | 原因 |
| --- | --- | --- |
| `helm`、`kubectl`、`Chart`、`Release` | 保留英文 | 实测这两个演示页的听感可接受，用户已认可 |
| `oci://` | 写「O-C-I 前缀」 | 连着斜杠念会糊 |
| `REVISION` | 保留英文大写 | 与文档一致；若抽听念错，改写 `revision` 小写 |
| `--keep-history` | 写「keep history 参数」 | 前导双横线会被吞或念错 |
| `values.yaml` 等文件名 | 保留 | 听众反正要看屏幕 |
| 数字百分比 | 「百分之三十」「1.2.3」逐位 | 避免「一点二三点三」歧义 |

新增无法确定的词：先保留原写法，**人耳抽听那一段**，念错就换谐音或拆字母，并回写本表。

## 4. 内容边界

- 只讲页面上正在展示的东西（讲稿与第④屏步骤一一对应），不讲页面上没有的
- 每一步结尾一句「接下来」天然衔接下一步（自动播放链式前进的听感更顺）
- 不念源码、不念表格；表格类内容在讲稿里概括成一句

## 5. 交付前检查（人工，不可跳过）

- [ ] 通读一遍：有没有拗口的长句、生硬转折
- [ ] 专有名词对照 §3 过一遍
- [ ] gen_tts.py 自动校验全过（exit 0）
- [ ] 合成后**至少抽听 1 段**（建议抽第一段+随机一段），确认音色、语速、无吞字
- [ ] 抽听发现问题 → 改讲稿 → 重新合成（脚本幂等，只重生改过的段）
